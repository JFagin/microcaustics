# microcaustics notebooks

These notebooks use only the installed public package API. Start Jupyter from
the package root after installing `microcaustics[notebooks]`.

```bash
pip install -e ".[notebooks,science,macro]"
jupyter lab examples/notebooks
```

The complete collection uses `science` for astronomy and reference numerics.
It uses `macro` for the strong-lens renderer and therefore requires Python
3.11 or newer. Install only `[notebooks,science]` on Python 3.10 and skip the
macro-rendering tutorials.

The distributed notebooks are intentionally output-free. Each
performance-sensitive notebook prints the runtime that produced its results
when executed. Generated figures, animations, and numerical products are
written to ignored local output directories rather than committed to the
repository. The README includes one representative documentation animation.

The current tutorial code uses seed 0, with subsequent integer seeds for
independent realizations. Changing the seed changes the physical realization,
not just its label. The library still draws fresh random inputs when you omit
a seed.

Package-owned figures are generated by notebook cells through the public
`microcaustics` interface. Maps, sources, transfer functions, light curves,
and method schematics are built from live package objects rather than archived
diagnostic arrays. The Weisenbach IPM and SIM5 notebooks are the two external
validation exceptions because one side of each comparison comes from an
independent solver.

Centered square source-independent maps use `map_width_uas` and `map_pixels`.
The few explicit `PlaneGrid` objects occur in advanced method or validation
cells that require rectangular, off-center, or exactly registered geometry.

The first notebook reports the operating system, PyTorch/CUDA versions, GPU
model, first-call time, and warmed steady-state time. Its first-call number may
reuse an on-disk compiler cache and is therefore not described as pure compile
time.

Triton needs a writable compiler cache. Its ordinary user cache is normally
appropriate. On a managed system, set `TRITON_CACHE_DIR` to a writable local
directory before starting Jupyter. Do not place it on a slow network drive.

The Weisenbach-IPM and SIM5 notebooks are optional. To run those external
comparisons, configure the products with `MICROCAUSTICS_WEISENBACH_NPZ`,
`MICROCAUSTICS_WEISENBACH_FRAME_NPZ`, and `MICROCAUSTICS_SIM5_DIR`. They
explain what is being compared and stop cleanly when those files are absent.

## Suggested order

The collection is grouped by purpose rather than presented as one long
sequence shown below.

- `getting_started/00_static_maps_and_numerical_methods` combines runtime
  selection, honest first-call/warmed timing, IRS and IPM, and the scout/full/
  rectangle integration domains.
- `getting_started/01_q2237_production_light_curve_and_gif` is the primary
  end-to-end introduction. It creates a ten-year Q2237 image-B-like dynamic
  calculation with a full-Kerr disk, daily source variability, sparse maps,
  center labels, and a 147-frame GIF.
- `getting_started/02_dynamic_maps_and_light_curves` isolates multirate map
  and source evolution, streaming, and selective map retention.
- `methods/` covers stellar populations, the local-exact complex-Taylor far
  field, and complete caustic/label products.
- `source_models/00_relativistic_disks_and_reverberation` combines the Kerr
  disk, variable-disk and transfer-function animations, and continuum
  reverberation without microlensing. The remaining source notebooks cover
  expanding supernovae, arbitrary custom sources, spectral microlensing, and
  selectable or user-defined viscous disk profiles.
- `workflows/` covers multi-image observations, macro-image rendering, a full
  lensed-quasar calculation, streaming/export, and one consolidated dataset
  notebook with fixed-system and prior-sampled training sets. The observation
  workflow selects a seeded six-band WFD cadence from an external Rubin OpSim
  database. The dataset notebook directly executes
  `batched_system_light_curves` for complete independent realizations and
  applies the same seeded cadence to its generated curves. The batching API
  also accepts mixed single- and multi-image systems, prepares compatible Kerr
  sources in independent batches, and can write either flat files or one
  combined NPZ archive.
- `validation/` contains the independent Weisenbach and SIM5 comparisons,
  convergence/performance studies, and the analytic single-point-lens test.

The primary Q2237, end-to-end, streaming, and performance notebooks should be
run on CUDA before a performance-sensitive study. They select strict Triton
execution when available, print the detected device/backend, and retain an
explicit portable fallback for inspection on CPU-only systems.
